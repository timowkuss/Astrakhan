# Подключение Kaspi Pay

Статус: в магазине работает только тестовая оплата. Реальные платежи не подключены. Реквизиты ИП будут предоставлены владельцем позже.

## Доступные пути

Официальный Kaspi Гид описывает удалённую оплату: счёт на номер покупателя или ссылка, которую можно разместить на сайте. Источник: https://guide.kaspi.kz/partner/ru/pos/payments/general/q1861 (проверено 15 сентября 2026).

Ссылка из Kaspi Pay сама по себе не даёт серверу магазина подтверждение платежа. Для первого запуска возможны ссылка и ручная сверка сотрудником. Для автоматического подтверждения требуется согласованный с банком либо выбранным платёжным провайдером интерфейс, его документация и серверные доступы. API заказов Kaspi Магазина не является API приёма платежей на нашем сайте.

## Что нужно получить от владельца

- Название ИП и реквизиты для отображения продавца.
- Подтверждение подключения бизнеса к Kaspi Pay.
- Официальную ссылку оплаты из Kaspi Pay, если выбирается ручная сверка.
- Для автоматического сценария: выбранный сервис, документацию создания/проверки платежа и тестовые доступы. Секреты хранятся только в серверном окружении, вне Git.

## Следующая реализация после выбора способа

1. Создавать неоплаченный заказ со снимком цен и состоянием `awaiting_payment` до перехода в Kaspi.
2. Резервировать остатки на ограниченное время; освобождать при отмене и истечении срока.
3. Сохранять идентификатор платежа, сумму в тиынах, валюту KZT, срок действия и ссылку.
4. Подтверждать оплату только после сверки сотрудником с Kaspi Pay либо проверенного серверного ответа провайдера. Переход на страницу успеха и скриншот чека не подтверждают поступление денег.
5. При автоматической интеграции проверять подпись уведомления, сумму, валюту и принадлежность платежа; повторные уведомления обрабатывать один раз. Восстанавливать статус после прерванного перехода из приложения банка.
6. Проверить успешную оплату, отказ, задержку, повторный запрос, истечение резерва и возврат.

Точки изменения: `lib/server/providers.ts`, `lib/server/orders.ts`, `app/api/[...path]/route.ts`, `app/storefront.tsx`, `app/admin-ui.tsx` и миграции `drizzle/`. Текущий интерфейс `PaymentProvider.confirm` синхронный и рассчитан на mock: для реальных платежей его необходимо расширить до создания и проверки платёжной сессии. Одних реквизитов ИП для автоматического списания и подтверждения недостаточно.
